# 公開リポジトリとしてのコミット指針

このリポジトリは GitHub で公開している（`CatHut/Extended_Project_TCC`。Unity Technologies Japan の `unity3d-jp/Project_TCC` のフォーク）。push した内容は誰でも読め、あとから消しても履歴・フォーク・キャッシュに残る。コミットする前に、この指針に沿って中身を確認する。

Claude はコミット前に PUB-00400（コミット前の確認手順）を必ず行う。

## PUB-00100: 基本方針

- **迷ったらコミットしない**。公開してよいか判断できないものは、コミットせずにユーザに確認する
- このリポジトリの文書・コメント・コミットメッセージは、**このリポジトリだけを clone した第三者が読む**ものとして書く
- 一緒に開発しているほかのリポジトリ（作業環境のルートのリポジトリを含む）は、**公開されていると確認できるまで非公開として扱う**。この文書にもそれらのリポジトリ名は書かない

## PUB-00200: コミットしないもの

### 認証情報

- API キー・アクセストークン・パスワード・秘密鍵・証明書・Android の keystore
- `.env`、サービスの設定ファイル（クラウドサービスのプロジェクト ID や接続文字列を含むもの）
- Unity Cloud / Unity Gaming Services の秘密情報（`ProjectSettings/` に入るプロジェクト ID 程度は除く）

### 個人を特定できる情報

- メールアドレス・本名・住所などの個人情報（文書・コード・コメント・アセットのメタデータ）
- ユーザ名やマシン名を含む**ローカルの絶対パス**（`C:\Users\<ユーザ名>\...`、`D:\Documents\...` など）。パスはリポジトリのルートからの相対パスで書く
- ログ・クラッシュレポート・スクリーンショットに写り込んだ個人情報

### 非公開リポジトリの内容

- 非公開リポジトリのソースコード・アセット・設定ファイルのコピー
- 非公開リポジトリの内部情報: ファイルパス、クラス名、コミットハッシュ、ブランチ名、チケット番号（`ISS-xxxxx` など）、仕様やゲームの内容
- 非公開リポジトリでの改造を取り込むときは、**変更の内容だけ**を書く（「〜という問題があったので〜を直した」）。どこから持ってきたかを書く必要がある場合は「別プロジェクトでの改造」程度にとどめる

### 再配布できないもの

- Asset Store などで購入したアセット、有料フォント、ライセンスが確認できない素材（画像・モデル・音・フォント）
- 新しい外部素材を追加するときは、ライセンスが公開リポジトリでの再配布を許しているかを確認し、出典とライセンスを記録する。確認できなければコミットしない

### 環境ごとに変わるもの・意図しない差分

- エディタ・IDE の個人設定: `UserSettings/`、`.vscode/`、`.vs/`、`*.csproj`、`*.sln`、`*.slnx`（`.gitignore` にないものは追加を提案する）
- 動作確認でたまたま変わっただけのシーン・Prefab・アセット・`SaveData/` の中身。作業の目的と関係のない差分はコミットしない
- `Library/`・`Temp/`・`Logs/`・ビルド成果物（`.gitignore` 済み）

## PUB-00300: 書き方の注意

文書（`docs/`・README）、コードのコメント、コミットメッセージのすべてに当てはまる。

- **リポジトリの外を前提にしない**: ワークスペースの規約の項番（`WR-xxxxx` など）、ワークスペースのスクリプト（`scripts/deps.py` など）、リポジトリの外を指す相対パス（`../../` など）は、第三者には意味が分からない。必要な手順や理由は、このリポジトリの中で完結するように書く
- **作業ログ**: チケットの作業ログも公開される。非公開リポジトリのファイル名やコミットを根拠として書かない
- **元の作者の文書を更新するとき**: `README.md`・`CONTRIBUTING.md`・`Documentations/` は元リポジトリから引き継いだもの。コンポーネントの追加・変更に合わせて更新してよいが、ライセンスとクレジットの表記は消さない。`LICENSE` は変更しない。設計の経緯や改変の理由は `docs/` に書く

## PUB-00400: コミット前の確認手順

Claude はコミットする前に次を行い、問題があればコミットせずにユーザに報告する。

1. `git status` で、ステージするファイルがすべて作業の目的に沿っているか確認する（未追跡ファイル・意図しない変更を含めない）
2. `git diff --cached` で、ステージした内容を読む。バイナリ（画像・モデル・音・フォント）が含まれる場合は、出所とライセンスを確認する
3. ステージした内容を次のパターンで検索し、該当したら PUB-00200（コミットしないもの）に当たるかを判断する

   ```sh
   git diff --cached -U0 | grep -nIE '[A-Za-z]:[\\/](Users|Documents)|/Users/|@[A-Za-z0-9.-]+\.(com|jp|net)|api[_-]?key|secret|token|password|BEGIN [A-Z ]*PRIVATE KEY'
   git diff --cached -U0 | grep -nIE 'UnityWorkspace|Reference/|WR-[0-9]{5}|ISS-[0-9]{5}|deps\.py|<ほかのリポジトリ名>'
   ```

   - 1行目: 認証情報・個人情報・ローカルの絶対パス
   - 2行目: ほかのリポジトリや作業環境への言及。`<ほかのリポジトリ名>` は、作業環境にあるほかのリポジトリの名前を `|` でつないで置き換える（このリポジトリ内のチケット番号 `TSK-xxxxx` は対象外）
   - 誤検出（Unity の URL、元の作者のクレジットなど）は除外してよい
4. コミットメッセージにも 3 と同じ観点で問題がないか確認する

## PUB-00500: push 前の確認

- push は毎回ユーザに確認してから行う。そのとき、push するコミットの一覧（`git log --oneline origin/main..HEAD`）を示す
- push していないコミットに問題が見つかった場合は、push 前に直す。履歴を書き換える必要がある場合（amend・rebase）はユーザの指示を得てから行う

## PUB-00600: 誤って公開してしまった場合

- **認証情報**: 履歴から消しても漏えいは取り消せない。まず該当のキー・トークンを無効化して再発行するよう、ユーザに伝える
- **それ以外**: 最新の状態から削除するコミットを作る。履歴からの削除（履歴の書き換え・force push）は、ユーザの明示的な指示がある場合だけ行う
- どちらの場合も、気づいた時点でユーザに報告する
